# ARTales source archive bucket — explicit production setup plan

Proposed bucket: `artales-source-archive`, private (`public=false`), 10 MB per file, original MIME types image/gif, image/png, image/jpeg. Supabase Storage persists objects with content-addressed immutable paths generated by `illustrationArchiveChoice`. The existing `artales-images` public bucket (PNG/JPEG/WebP, 5 MB) continues unchanged for approved Reader derivatives.

## Authorization and security
This is a **proposal, not a deployed bucket**. ARTales currently has only its production Supabase branch and no ephemeral preview branch. Do not apply storage DDL or change RLS without a separate explicit production DB/Storage authorization. The bucket must never receive a public-read policy. Client `anon` / `authenticated` must have no direct write/update/delete/read policies. A narrowly authenticated server-side ingest route validates editor/admin assignment and hashes; provisioning must be paired with its tested secure service access. The no-upsert adapter is readback-verified. Never expose a service-role/secret key in browser code or publicly accessible endpoint.

If direct editor previews are added, use short-lived signed URLs only after server authorization, or proxy requests with authorization checks. Keep raw assets private even when publication selects a derivative. Avoid creating public signed URLs for protected sources.
